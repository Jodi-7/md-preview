## 2. F1 目录内全文搜索

### 2.1 接口

```ts
interface SearchHit { path: string; name: string; line: number; snippet: string }
interface Library {
  ...
  /** 可选：全文搜索。没有实现的能力（demo 除外）由调用方降级 */
  search?(query: string): Promise<SearchHit[]>
}
```

三种实现的差异全部收在 `Library` 内部，界面层只调用 `library.search(query)`：

| 实现 | 做法 | 上限 |
| --- | --- | --- |
| 桌面版（`desktop.ts`） | 新 IPC `fs:search`，主进程对扫描清单逐文件 `readFile` 匹配 | 单进程内循环，200 条 |
| 句柄库 / 拖拽库（`files.ts`） | 遍历 `docs` 逐个 `readDoc` 匹配；无缓存，每次现读 | 同上 |
| 快照库 / demo | 与句柄库同一条路（内容在内存或可读） | 同上 |

### 2.2 关键决策

- **不建索引**。目标场景是几百个文件的文档库，逐文件线性扫描 1 s 内可完成；建索引要处理失效、持久化、内存占用，违背「无状态、可随时丢弃」的库设计。
- **匹配是纯函数**（`lib/search.ts` 的 `matchLines`）：大小写不敏感、按行匹配、每文件最多 8 条命中、全局 200 条封顶、片段裁到 160 字符。UI 与 IO 都不进这个模块，单测只测它。
- **UI 挂在 FileTree 搜索框**，新增「文件名 / 内容」模式切换。关键词 ≥ 2 字符、防抖 250 ms 才触发；请求带递增序号，只有最新一次的结果会落地（防快速输入串台）。
- **点击命中项** = `openTab` + 预览滚动到命中行。滚动复用 `data-line` 标记与 `scrollPreviewToLine`，经 `pendingJump` ref 在标签打开后的 effect 里执行一次。

## 3. F2 大文档分块渲染

### 3.1 管线变化

```
renderMarkdown(text)                      -- 不变，仍整篇渲染 + 净化
  → splitIntoChunks(html)                 -- 新：DOMParser 按 h2 边界切块
  → DocumentView 首屏只挂载首个块          -- 既有后置增强按「已挂载块数」重跑
  → requestAnimationFrame 逐帧挂载后续块    -- 每帧 2 块，全部挂完为止
```

### 3.2 关键决策

- **阈值**：渲染结果 < 4000 个 DOM 节点（DOMParser 时统计）走原来的单块路径，行为完全不变；超过才分块，每块 ≤ 1200 节点、新块最小体量 400 节点。普通文档（包括 demo）零影响。
- **自适应批量补块**：不是固定「每帧 2 块」——两次调度间隔 >120ms 说明单帧太重，批量减半；<60ms 则加一（上限 8）。大块重排贵的文档批量自动收敛，实测 6.35 MB 文档 2.5 s 可见 45%、8.4 s 挂完。注意 rAF 依赖页面可见，最小化时暂停、恢复后继续。
- **编辑防抖不受影响**：分块只发生在 `html` 变化之后，挂载调度以 `html` 为 key 重启；140 ms 防抖内连续输入只会重启一次调度，已挂载内容立即被新 html 替换，不会叠加。
- **后置增强逐块生效**：五个 effect（复制按钮/图片/Mermaid/KaTeX/大纲）的依赖从 `[html]` 改为 `[html, mountedCount]`，内部已有的幂等保护（`dataset.enhanced`、`dataset.local`、pre 被替换后消失）保证重复执行安全。
- **滚动同步**：`data-line` 跟随块一起挂载；分块期间的几百毫秒里映射暂时不全，`scrollPreviewToLine` 找不到更靠后的块只是暂不滚动，与现状一致。镜像量尺不需要重测（它只量编辑器一侧）。
- **大纲**：挂载完成后重新采集，期间大纲暂缺后续标题，与滚动映射同理。

### 3.3 放弃的方案

- Web Worker 里切分：切块本身 < 10 ms，不值得引入通信开销。
- 虚拟滚动（滚动到哪渲染哪）：状态机复杂度远超收益，且会破坏 Ctrl+F / 打印 / 锚点跳转。

## 4. F3 拖拽文件进会话

### 4.1 来源模型扩展

`LibraryOrigin.kind` 与 `StoredTab.kind` 新增 `'snapshot'`，`StoredTab` 新增 `text?: string`（快照内容）。快照库也带 `origin`，从此**所有来源都有会话能力**，粘贴文本同样受益。

| 来源 | kind | 恢复方式 | 监听/保存 |
| --- | --- | --- | --- |
| 目录句柄 | `dir` | 句柄 + 授权（现状） | ✔ |
| 文件句柄 | `file` | 句柄 + 授权（现状） | ✔ |
| 桌面路径 | `path` | 绝对路径（现状） | ✔ |
| **拖拽/粘贴快照** | `snapshot`（新） | 存进 IndexedDB 的文本内容 | ✘，只读 |

### 4.2 桌面版拖拽：改走 `webUtils`

Electron 新版本已弃用渲染进程的 `File.path`。preload 里通过 `webUtils.getPathForFile(file)` 暴露 `desktopBridge.pathForFile(file)`，App 的拖放分支优先用它，`file.path` 仅作兜底。取到路径后仍走 `libraryFromDesktop`，与命令行打开同一条路（可监听、可保存、可恢复）。

### 4.3 网页版快照

- `files.ts` 新增 `libraryFromSnapshot(entries, rootName)`：用内存文本构造目录库（多文件）/单文件库，`watchable: false`，`origin.kind = 'snapshot'`，`resolveAsset` 返回 null（快照没有目录上下文，图片降级为占位，与单文件模式一致）。
- `App.openFiles` 给 `libraryFromFiles` 的产物补上 `origin: { kind: 'snapshot' }`；`libraryFromText` 同样补。
- **持久化上限**：单文件 > 2 MB 不入会话（恢复时提示）；会话总快照 ≤ 12 MB，超出按最旧丢弃。上限写进常量，避免 IndexedDB 膨胀。
- 恢复时按 `rootName` 分组重建快照库，`openTab` 逐个打开；恢复后 toast 提示「N 篇快照文档不支持自动刷新」一次。

## 5. 同步手感优化

预览→编辑器方向原来是「跳到最近映射块的行首」，短块密集时会有台阶感。改为：取视口顶部命中的映射块与其后一块，在两块的行号之间按滚动比例**线性插值**，再落到编辑器偏移。`scrollSync.ts` 新增纯函数 `interpolateLine(hits, probe)`，DOM 部分保持薄壳，插值逻辑可单测。

## 6. 验证策略

1. **单元测试**（新增 vitest，纯函数为主）：`matchLines`、`splitIntoChunks`、`interpolateLine`、`lineAtOffset`、桌面路径工具（`resolveInside` 导出后可测）。DOM 无关，node 环境跑；仅 chunks 用 jsdom。
2. **CDP 真机断言**（`tools/shot.mjs`）：demo 页回归（公式/表格数量）；搜索交互（输入关键词 → 结果数量）；桌面版 `--bin=` 指向打包 exe，用生成的大文档断言分块生效、搜索 IPC 返回命中。
3. **构建即校验**：`pnpm build`（tsc 严格模式）+ `pnpm scan` 保持 CLEAN。
