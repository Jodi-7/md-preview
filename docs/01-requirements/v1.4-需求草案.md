# v1.4 需求草案 · 找到内容

> 状态：草案。定稿后并入[需求文档](需求文档.md)。范围讨论见[需求文档 3.2 明确不做](需求文档.md)。

## 1. 版本主题

v1.3 完成了「看得舒服、改得顺手」。v1.4 解决「找不到内容」：文档库一多，缺全文搜索；大文档打不开；拖进来的文件刷新就丢。三个功能都直接命中现有定位（本地阅读器）下的真实缺口，不引入新依赖方向。

## 2. 功能需求

### F1 目录内全文搜索（优先级最高）

在当前目录库的所有 `.md` 文件内容里搜索关键词，展示命中的文件与所在行摘要，点击跳转到该文件该位置。

| 项 | 要求 |
| --- | --- |
| 入口 | `FileTree` 搜索框新增「文件名 / 内容」两种模式 |
| 桌面版 | 新增 IPC，主进程逐文件匹配（复用扫描文件清单，跳过非 md） |
| 网页版 | 复用 `readDoc` 逐文件读取匹配；目录授权下可用，单文件模式不提供 |
| 限制 | 命中上限（如 200 条）防止极端目录卡死；不建索引，保持无状态 |

验收：百文件级目录搜索 1 s 内出结果；跳转后目标行可见。

### F2 大文档分块渲染

整篇 HTML 一次注入改为按二级标题切块，首屏渲染前几块，滚动到附近再渐进注入。目标：约 18 万 DOM 节点的极端文档从 10 s 降到**首屏 1 s 内**。

| 项 | 要求 |
| --- | --- |
| 切块 | 渲染后按 `h2` 分段；无 `h2` 的文档维持现状 |
| 复用 | 占位 + 渐进机制与 Mermaid/KaTeX 懒加载同思路；大纲、行号、图片、公式在各块注入后照常工作 |
| 风险 | 行号标记与滚动同步的坐标在分块注入期间要一致，`scrollSync` 量尺需在全部块就位后重测 |

验收：极端大文档首屏可交互；分块期间搜索跳转、双栏同步不偏移。

### F3 拖拽打开的文件进会话

消除「按路径打开能恢复、拖拽打开不能」的不一致。

| 项 | 要求 |
| --- | --- |
| 桌面版 | 拖拽文件统一取路径（Electron `File.path`），走 `libraryFromDesktop`，与命令行打开同一条路，可监听、可恢复 |
| 网页版 | 拿不到句柄，把文件**内容快照**存入 IndexedDB 恢复（无监听、无保存，符合降级策略） |
| 会话 | 快照设大小上限（如单文件 2 MB），超限不入会话并提示 |

验收：桌面版拖拽打开的文件刷新后回来且自动刷新；网页版刷新后内容回来但只读提示明确。

## 3. 现有功能优化

| 项 | 说明 |
| --- | --- |
| 滚动同步手感 | 双栏对齐从纯像素行改为标题块锚点对齐；`useScrollSync` 的 `guard` 时长回归测试 |
| 内置示例更新 | `src/lib/demo.md` 仍写「公式（KaTeX）规划中」，与 v1.3 实际能力不符，随本版修正 |

## 4. 明确不做（沿用 v1.3 边界）

- 不换 Tauri 减体积（界面零改动的价值大于 300 MB 的下载成本）
- 不升级 CodeMirror（「顺手改两笔」定位下 textarea 是正确轻量）
- 不做导出 PDF/HTML、文件管理、云同步（见[需求文档 3.2](需求文档.md)）

## 5. 非功能指标

| 指标 | 目标 |
| --- | --- |
| 首屏体积 | 不超过 190 KB gzip（新增代码不进首屏，搜索走懒加载） |
| 大文档 | 首屏内容绘制 < 1 s（18 万节点级） |
| 隐私 | 全文搜索纯本地匹配，无任何上传；`pnpm scan` 保持 CLEAN |
